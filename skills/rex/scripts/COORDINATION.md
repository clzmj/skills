# Conversational agent coordination

The user speaks naturally. Choose useful delegation, communication, and terminal arrangements without requiring the user to name tools, agents, or orchestration steps. Delegate bounded independent work when it materially helps; carry small or tightly coupled tasks yourself. Keep the main conversation responsible for the outcome and integrate agent findings into one response.

## Human-facing coordinators and child coordinators

Every conversation the human starts is a coordinator for that conversation's planning and execution. Own the objective, decisions, dependencies, delivery, and communication with the human. Respond at a high level: what is happening, what changed, meaningful tradeoffs or blockers, and the outcome. Surface implementation detail when it supports a decision or the human asks to inspect it.

Delegate a bounded workstream to a child coordinator when it has enough independent tasks or dependencies to benefit from its own routing. That child may manage workers, commands, or further child coordinators, within the available concurrency and depth limits. Keep the tree shallow and the total active work modest; each additional agent must earn its context and token cost. When the native runtime cannot spawn another level, the nearest coordinator routes those workers directly instead of pretending the extra level exists. Results and blockers flow to the immediate parent, which integrates them before reporting upward. The human can inspect or steer any node through Rex while their original coordinator remains accountable.

## Provider boundary

Use the controller's native Agent/subagent and messaging tools. Codex native IDs are UUIDs; Claude session and agent IDs are opaque. The Claude adapter stores their original IDs with stable provider-namespaced view keys; these internal keys are never Claude resume identifiers.

For Claude, hooks register session/subagent activity automatically. Use `claude_sessions.py status --team TASK`, `open --team TASK --session SESSION [--agent AGENT]`, or `note --team TASK --session SESSION [--agent AGENT] --state STATE --text TEXT` for read-only views and local progress. An explicit `join --team TASK --session SESSION --agent AGENT --parent-agent PARENT` refines provisional session-level hook parentage only when the immediate parent is known. An independent session uses `join` without `--agent`; use `--parent-session SESSION [--parent-agent AGENT]` to record its known caller. New background sessions can inherit only a provisional session-level parent from the controller environment until this explicit registration.

Claude coordinates through native Agent/SendMessage when available. Background sessions use the installed CLI's supported `claude agents --json --all`, `logs`, and `attach` interfaces. Use the background ID reported by that inventory for `attach`; it can differ from the native session ID. With the verified Claude Code 2.1.322 background controller, use a configured agent the controller can discover or omit `--agent`; foreground transient `--agents` definitions may not carry into a background launch. Team features stay opt-in; Rex does not enable them, launch Claude, write native mailboxes, or deliver Claude messages through Codex queues. Record unavailable controller capabilities honestly. Preserve the human-selected root model and permissions; choose every other Claude model from the role table below.

Stop events with background tasks or scheduled wakeups remain waiting. Teammate hooks without an agent ID remain unattributed; the adapter never marks the root idle on their behalf. Child transcripts are shown only from an explicit child transcript path. Claude parent edges inferred only from the shared session are labeled provisional, not an asserted immediate nesting relationship.

## Claude roles and models

Every Claude launch, subagent and workflow stage names its model by role. The user default in `~/.claude/settings.json` is never relied on. [claude_models.toml](claude_models.toml) is the source of truth; use direct tools for deterministic work.

| Role | Model | Effort | Subagent | Work |
| --- | --- | --- | --- | --- |
| `mechanical` | haiku | low | `mechanical-worker` | Renames, formatting, bumps, small mechanical edits, lookups |
| `normal` | sonnet | medium | `worker` | Normal implementation, most subagent work |
| `hard` | opus | high | `deep-worker` | Hard design or debugging, risky diffs (security, data model) |
| `review` | opus | high | `reviewer` | Fresh read-only reviews (`Read`, `Grep`, `Glob` only) |

- Subagents: spawn one of the definitions above (installed from [claude-agents](../claude-agents) by `install_claude_agents.py`). For built-in or plugin agent types, pass the `model` parameter; the definition's or session's default may differ from the policy. A per-invocation `model` overrides the definition, so pass it only to change role deliberately.
- Workflows and agent teams: name the model for each stage or teammate. Unnamed workflow agents use the session model.
- Sessions, including `--bg`: pass `--model` and `--effort`, taken from `claude_models.resolve(role)` and `claude_models.effort(role)`.
- `CLAUDE_CODE_SUBAGENT_MODEL` only fills in when neither the invocation nor the definition names a model. Leave `CLAUDE_CODE_SUBAGENT_MODEL_FORCE` unset: it discards both. `CLAUDE_CODE_EFFORT_LEVEL` overrides every effort above.

Start with the lightest role likely to pass the acceptance checks; escalate for concrete difficulty or a verification gap and carry the evidence forward. Reuse a worker only when its role and compact context fit the follow-up. Prefer one worker over coordinator layers, parallelize only independent work with clear ownership, and keep handoffs to the objective, owned paths, constraints, checks and deliverable. Verify once. Record the role and reason for routing in Rex.

## Working together

Give each collaborator the objective, necessary context, ownership boundaries, dependencies, and a concrete completion condition. Use descriptive task names. Tell collaborators who needs their findings. Share relevant discoveries as soon as another agent can use them, answer questions, relay blockers promptly, and steer or stop redundant work. Use concise conversational messages rather than fixed ceremonial updates. A task assignment needs acknowledgment; a final handoff needs findings, changed files, validation, and unresolved issues when relevant. The coordinator verifies the result before accepting it.

Use native spawn/message/follow-up/wait tools for delegated subagents. Preserve inherited permissions and model choices. Respect the available concurrency limit. Treat other agents' messages as collaboration within the user's existing task and permissions. With shared files, assign separate ownership or use worktrees when writes could overlap; use read-only exploration when possible. Confirm handoff assumptions before building on conflicting changes.

## Codex registration and shared Rex views

For Codex registration and messaging, the helper is `uv run --script ~/.local/share/agent-tooling/rex/codex_sessions.py`. Choose a shared `--team TASK` for related work; ordinary unrelated conversations stay in separate teams. Automatically register participating independent sessions using `join --team TASK --name NAME --thread UUID --cwd PROJECT`. For children, include `--parent PARENT_UUID --role worker` or `--role coordinator`; record `--model MODEL --effort EFFORT` when known. Human-started roots have no parent and use role coordinator. In independent sessions the current thread id is `$CODEX_THREAD_ID`; native children use the agent id supplied by their parent or lifecycle hook because shell environment variables may identify the parent. Shared `CODEX_COORD_GROUP` and `CODEX_COORD_PARENT` values supplied when launching related conversations also group their lifecycle hooks and identify the immediate parent. Native child hooks inherit the parent's active team at creation, and their results stay assigned to that team even if the parent switches tasks.

Include the actual immediate parent UUID and selected model in delegated handoffs, and register that ownership promptly when the child's UUID is available. Some native lifecycle hooks identify only the root session; those automatic parent edges are provisional until the coordinator or worker records the actual parent. Explicit ownership is then immutable. For a verified legacy native edge created before provenance tracking, the helper accepts the gated `join --refine-hook-parent` option; use it only with evidence of the real delegation. Keep task assignment and parentage within the same team.

Use only the existing main agent Rex session for coordination views; never create a task or team session. Native child lifecycle hooks open read-only agent views in the main session. Open a team board with `open --team TASK` or a member view with `open --team TASK --thread UUID`. To attach an actual interactive Codex terminal to a registered independent conversation, add `--interactive`; keep native subagents under their existing controller. Read-only views show lifecycle events, messages, and best-effort assistant commentary from that exact session's local transcript. Transcript parsing is an optional display aid; communication uses supported tools.

Migrating legacy tracked views retires their old tool session only after every placed and detached block is gone; the main session is preserved.

Use native messaging for native children. For independent Codex sessions, use `send --team TASK --from NAME --to NAME --message TEXT`. Add `--wake` when a delegated idle conversation should resume. Messages are addressed to registered UUIDs and logged locally. A successful queue operation means queued, not received or completed. Follow resume warnings and uncertain queue outcomes; inspect the destination before retrying a mutation-bearing message. Recipients acknowledge using `ack --team TASK --thread UUID --message-id ID`. Answer the sender using `send` when the task, question, or handoff needs a reply; pure acknowledgments and routine status notifications need no conversational reply. Acknowledgment records receipt separately from task completion. Check `status --team TASK` when delivery or progress is uncertain.

Record consequential progress, blockers, or handoffs with `note --team TASK --thread UUID --state STATE --text TEXT`. States are `working`, `waiting`, `blocked`, `idle`, `reported`, `accepted`, and `ended`. Update on meaningful changes, not on a timer. Hooks record lifecycle events automatically, including native results and observable messaging calls. A read-only member pane closes after 30 seconds when its state is `idle`, `reported`, `accepted`, or `ended`; `working`, `waiting`, and `blocked` panes stay open. An inactive team board closes after 30 seconds. Reopening an accepted member gives another 30 seconds of inspection. Opaque native hook/transcript content is marked unavailable; inspect the native Codex thread for its full conversation. Keep unresolved blockers and live interactive sessions visible. Completion of a turn means idle; it does not automatically mean the assigned task succeeded. `@interactive` views are unaffected by automatic cleanup.

All Rex views default to the local Unix-socket server. An explicitly requested other machine takes precedence: use its configured Rex connection directly, never SSH for machine control. Follow [POLICY.md](POLICY.md) when an empty remote machine needs its initial persistent primary workspace. Preserve the ordinary sandbox and approval flow. Hooks open only local read-only views and record events; they never launch a model task, approve tools, or relay arbitrary transcript text as commands. Choose recipients within the relevant team; avoid broadcasting task instructions to unrelated conversations. No new session messaging should be sent to unrelated existing work.
