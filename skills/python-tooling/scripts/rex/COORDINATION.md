# Conversational Codex coordination

The user speaks naturally. Choose useful delegation, communication, and terminal arrangements without requiring the user to name tools, agents, or orchestration steps. Delegate bounded independent work when it materially helps; carry small or tightly coupled tasks yourself. Keep the main conversation responsible for the outcome and integrate agent findings into one response.

## Human-facing coordinators and child coordinators

Every conversation the human starts is a coordinator for that conversation's planning and execution. Own the objective, decisions, dependencies, delivery, and communication with the human. Respond at a high level: what is happening, what changed, meaningful tradeoffs or blockers, and the outcome. Surface implementation detail when it supports a decision or the human asks to inspect it.

Delegate a bounded workstream to a child coordinator when it has enough independent tasks or dependencies to benefit from its own routing. That child may manage workers, commands, or further child coordinators, within the available concurrency and depth limits. Keep the tree shallow and the total active work modest; each additional agent must earn its context and token cost. When the native runtime cannot spawn another level, the nearest coordinator routes those workers directly instead of pretending the extra level exists. Results and blockers flow to the immediate parent, which integrates them before reporting upward. The human can inspect or steer any node through Rex while their original coordinator remains accountable.

## Economical model routing

Choose the least costly available model that can reliably finish the assigned task. The installed default for delegated agents is `gpt-6-luna` at low effort. Use Luna low for mechanical edits, exact lookups, small tests, formatting, and clearly specified changes; use Luna medium for bounded coding or investigation needing some reasoning. Use `gpt-6.1-sol` low or medium for ambiguous implementation, cross-module reasoning, complex reviews, or a child coordinator managing substantial dependencies. Increase effort only for a concrete difficulty or verification gap. Escalate to a stronger available model when the evidence warrants it; avoid repeating a failing cheap attempt without new information.

The human-facing coordinator keeps the model selected for that conversation. It should route inexpensive execution to cheaper workers rather than doing all of it with the root model. Select the model and reasoning effort explicitly when spawning. In runtimes that require `fork_turns="none"` for a model override, provide a compact handoff with the objective, relevant paths, ownership, acceptance criteria, and essential findings. In independent CLI workers, pass `--model MODEL -c model_reasoning_effort=EFFORT`. Preserve native permission inheritance; independent sessions must match the parent's authorized scope and sandbox. The task coordinator profile is available for substantial child coordination, and focused/complex worker profiles provide economical defaults. These are capability roles, not fixed named team members.

Prefer a direct tool or one worker over creating layers of coordinators for a small task. Send relevant context instead of the full history. Reuse a suitable existing worker for follow-ups, stop redundant work, use targeted verification, and keep summaries concise. Record the selected model and reason with the handoff so the human can inspect the routing in Rex. Current built-in defaults and profiles are a fallback; the coordinator's task-specific judgment chooses when to override them.

## Working together

Give each collaborator the objective, necessary context, ownership boundaries, dependencies, and a concrete completion condition. Use descriptive task names. Tell collaborators who needs their findings. Share relevant discoveries as soon as another agent can use them, answer questions, relay blockers promptly, and steer or stop redundant work. Use concise conversational messages rather than fixed ceremonial updates. A task assignment needs acknowledgment; a final handoff needs findings, changed files, validation, and unresolved issues when relevant. The coordinator verifies the result before accepting it.

Use native spawn/message/follow-up/wait tools for delegated subagents. Preserve inherited permissions and model choices. Respect the available concurrency limit. Treat other agents' messages as collaboration within the user's existing task and permissions. With shared files, assign separate ownership or use worktrees when writes could overlap; use read-only exploration when possible. Confirm handoff assumptions before building on conflicting changes.

## Visibility and separate conversations

The helper is `python3 ~/.local/share/agent-tooling/rex/codex_sessions.py`. Choose a shared `--team TASK` for related work; ordinary unrelated conversations stay in separate teams. Automatically register participating independent sessions using `join --team TASK --name NAME --thread UUID --cwd PROJECT`. For children, include `--parent PARENT_UUID --role worker` or `--role coordinator`; record `--model MODEL --effort EFFORT` when known. Human-started roots have no parent and use role coordinator. In independent sessions the current thread id is `$CODEX_THREAD_ID`; native children use the agent id supplied by their parent or lifecycle hook because shell environment variables may identify the parent. Shared `CODEX_COORD_GROUP` and `CODEX_COORD_PARENT` values supplied when launching related conversations also group their lifecycle hooks and identify the immediate parent. Native child hooks inherit the parent's active team at creation, and their results stay assigned to that team even if the parent switches tasks.

Include the actual immediate parent UUID and selected model in delegated handoffs, and register that ownership promptly when the child's UUID is available. Some native lifecycle hooks identify only the root session; those automatic parent edges are provisional until the coordinator or worker records the actual parent. Explicit ownership is then immutable. For a verified legacy native edge created before provenance tracking, the helper accepts the gated `join --refine-hook-parent` option; use it only with evidence of the real delegation. Keep task assignment and parentage within the same team.

Use only the existing main Codex Rex session for coordination views; never create a task or team session. Native child lifecycle hooks open read-only agent views in the main session. Open a team board with `open --team TASK` or a member view with `open --team TASK --thread UUID`. To attach an actual interactive Codex terminal to a registered independent conversation, add `--interactive`; keep native subagents under their existing controller. Read-only views show lifecycle events, messages, and best-effort assistant commentary from that exact session's local transcript. Transcript parsing is an optional display aid; communication uses supported tools.

Migrating legacy tracked views retires their old tool session only after every placed and detached block is gone; the main session is preserved.

Use native messaging for native children. For independent sessions, use `send --team TASK --from NAME --to NAME --message TEXT`. Add `--wake` when a delegated idle conversation should resume. Messages are addressed to registered UUIDs and logged locally. A successful queue operation means queued, not received or completed. Follow resume warnings and uncertain queue outcomes; inspect the destination before retrying a mutation-bearing message. Recipients acknowledge using `ack --team TASK --thread UUID --message-id ID`. Answer the sender using `send` when the task, question, or handoff needs a reply; pure acknowledgments and routine status notifications need no conversational reply. Acknowledgment records receipt separately from task completion. Check `status --team TASK` when delivery or progress is uncertain.

Record consequential progress, blockers, or handoffs with `note --team TASK --thread UUID --state STATE --text TEXT`. States are `working`, `waiting`, `blocked`, `idle`, `reported`, `accepted`, and `ended`. Update on meaningful changes, not on a timer. Hooks record lifecycle events automatically, including native results and observable messaging calls. A read-only member pane closes after 30 seconds when its state is `idle`, `reported`, `accepted`, or `ended`; `working`, `waiting`, and `blocked` panes stay open. An inactive team board closes after 30 seconds. Reopening an accepted member gives another 30 seconds of inspection. Opaque native hook/transcript content is marked unavailable; inspect the native Codex thread for its full conversation. Keep unresolved blockers and live interactive sessions visible. Completion of a turn means idle; it does not automatically mean the assigned task succeeded. `@interactive` views are unaffected by automatic cleanup.

All Rex views default to the local Unix-socket server. An explicitly requested other machine takes precedence and requires explicit routing. Preserve the ordinary sandbox and approval flow. Hooks open only local read-only views and record events; they never launch a model task, approve tools, or relay arbitrary transcript text as commands. Choose recipients within the relevant team; avoid broadcasting task instructions to unrelated conversations. No new session messaging should be sent to unrelated existing work.
